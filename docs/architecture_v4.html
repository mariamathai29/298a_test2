1. What it does

A 4-tap FIR filter whose weights adapt by sign-sign LMS, for interference cancellation: the reference u feeds the FIR, the desired input r carries signal plus interference correlated with u, and the chip returns y (the interference estimate) and e = r − y (the cleaned signal). System identification uses the same datapath: it's the weights that are of interest there, read out over the debug path.

Per sample n, for k = 0..3:

y[n] = sat8( round( Σ x[n−k] · w[k] ) )    e[n] = sat8( r[n] − y[n] )    w[k] ← sat14( w[k] + μ · sign(e[n]) · sign(x[n−k]) )

sign(0) = 0. The update uses the same x vector that produced y[n]. μ = 2mu_sel weight-register LSBs, so mu_sel = 0 gives μ = 2−12.

3. Block diagram

4. The key idea: rotating rings instead of a read mux

v3 had the same blocks, but one MAC/update unit reached every tap and weight through a 4:1 mux and wrote every weight back through a decoder. That tied all 88 register bits (32 tap + 56 weight), scattered over the tile, to one central point and back. Global routing needed 168% of the only horizontal metal layer, and the router never closed.

In v4 the taps and weights are circular shift registers. Each MAC cycle uses position 0 and rotates both rings by one, so every register bit connects only to its neighbour. After 4 rotations the rings are back in order.

5. One step, cycle by cycle

Horner-order Booth multiply

Each 8-bit tap splits into four radix-4 Booth digits d3..d0 ∈ {−2, −1, 0, +1, +2}, so x = Σ 4jdj. v3 added each partial product at its own shift (a 4-way variable shifter). v4 runs the digit outer, tap inner:

acc = ((S3·4 + S2)·4 + S1)·4 + S0,   where Sj = Σk dj(x[k]) · w[k][13:4]

So acc only ever shifts by a fixed 2 bits (just wiring) at the start of each digit group, and the tap order within a group is exactly the ring rotation. The intermediate values stay within ±348k, inside the 20-bit accumulator.

6. Clock-domain crossing (no FIFO)

  1. On every rising SCLK_IN edge, the u and r lanes shift into 7-bit registers. A 3-bit counter, cleared while CS_IN is high, marks the 8th bit.
  2. On the 8th bit, the full words go into the 8-bit holding registers and d_tog flips.
  3. In the clk domain, a 3-flop synchronizer turns the toggle into a one-cycle d_stb, 2–3 clk later.
  4. On d_stb, the core copies hold u into the tap ring and hold r into r_q.

Why it's safe: the holding registers change again only at the next frame's 8th bit, at least 8 SCLK periods (16 clk) later, and the core reads them 2–3 clk after the toggle. The words are therefore stable when sampled, and only the single toggle bit actually crosses domains. STA treats the two clocks as asynchronous (set_clock_groups -asynchronous), so these paths are not timed. That's correct, because the toggle protocol makes them safe.

Rate rule: a sample arriving while a step (22 clk) or readout is busy is dropped and sets debug_o1. The host must leave at least 11 SCLK periods per sample; use 12 or more, since the strobe position moves by a clock when SCLK is asynchronous.

11. Open issues and next steps

  1. Slow-corner setup (−6.9 ns). Register the Booth partial product, splitting the critical path roughly in half. Cost: about 12 flip-flops (~900 µm², taking utilization to ~87%) and 1 extra clock per step (23 clk, max 2.17 MS/s, still above 2 MS/s). Whether the course requires slow-corner closure is worth checking with the instructor; typical and fast corners already pass.
  2. Utilization at 85% leaves little margin for changes. The next easy saving is 12-bit weights (Q2.10, about 1,000 µm²), at the cost of a coarser minimum step (μ ≥ 2−10).
  3. I/O timing is generic. Input and output delays are 20% of the clock period. They are not derived from Tiny Tapeout's pad and mux delays. Running SCLK_IN, SCLK_OUT and data at 25 MHz through the TT I/O mux should be checked against TT's GF180 I/O specs.
  4. 2.000 MS/s exactly isn't a whole number of 25 MHz SCLK periods; pick 12 or 13 periods, or change SCLK.
  5. Testing on the TT board: the course expects cocotb tests. This regression could be ported to cocotb with lms_model.py as the scoreboard.
